## 1. 仓库组织方式

| 项目 | 说明 |
|---|---|
| 仓库形式 | **单一仓库（monorepo）**，仓库根目录即项目根目录 `Trade/` |
| 主分支 | `main` |
| 远端 | `https://github.com/zhangzhanglaila/Trade.git`（**公开仓库**） |
| 仓库根 | 与 `src/`、`data/`、`docs/` 同级 |
| 历史备份 | `D:\Code\_git备份_20260927.tar.gz`（合并前 13 个嵌套仓库的完整 `.git`） |

> ⚠️ **远端是公开仓库**：提交前请确认没有把 `config/.env`、明文口令或 API Key 加进来。
> 相关约定见 §8。

### 1.1 为什么合并成一个仓库

合并前项目内散落着 **13 个各自独立的 Git 仓库**（含 3 个 submodule、2 个第三方库、2 个模型仓库）。
由此带来三个问题：

1. **无法整项目版本管理**：在根目录执行 `git status` 什么也看不到，改动散落在十几个仓库里。
2. **嵌套仓库会互相干扰**：外层仓库遇到内层 `.git` 时会把它当作 gitlink/子模块处理，
   内层文件不会进入外层历史，`git add` 会产生 "embedded repository" 警告。
3. **无统一提交边界**：一次功能改动若跨前端与后端，无法用一个 commit 表达。

因此统一为单一仓库：根目录一次 `git add .` 即可完整记录项目状态。

## 3. 被排除内容的恢复方法

### 3.1 大模型（18.5 GB）

两个模型均有独立远端，可重新拉取：

```bash
# 合并后的模型（vLLM 本地部署用）
git clone https://hf-mirror.com/xidrug/qwen3.5-9b-kh-trade-logistics-merged-v1

# 训练用基座（含 SFT 数据）
git clone https://github.com/xidrug/qwen3.5-9b-kh-trade-qa.git
```

拉取后放回 `models/` 对应子目录即可，后端通过 `application.yaml` 中的路径读取。

### 3.2 数据集（2.18 GB）

`data/` 下 7 个数据集目录（`01_原始_` ~ `07_派生_`）由交付包/RDF 文件单独分发。
每个目录内的 `README.md` 已入库，可据此确认缺失内容与用途。

### 3.3 训练权重（113 MB）

`src/backend-training/python-scripts/model/trade_Transformer/{in,out}/*.pth`
（共 8 个文件，`model_*` 与 `checkpoint_*` 各 4 个）。

- `in/` —— 首次训练产物；`out/` —— 二次训练产物
- 训练曲线图（`.png`）与标签编码器/归一化器（`.pkl`）**已入库**，可用于核对训练结果
- 需要重新训练时执行 `python-scripts/Trade_Transformer_LSTM_{price,quantity}.py`

### 3.4 AJ-Report 大屏依赖（112 MB）

`src/dashboard-ajreport/lib/` 为 AJ-Report 1.3.0 的第三方 jar 包集合。
从 AJ-Report 官方发布页下载 `aj-report-1.3.0.RELEASE` 发行包，把其 `lib/` 复制回来即可。
`bin/`、`conf/`、`aj_report.sql`、`dashboard.json` 等配置已在库中。

## 5. 换行符策略（`.gitattributes`）

项目需要同时在 **Windows 开发机** 与 **Linux 服务器** 上运行，因此统一换行符：

| 文件类型 | 仓库内 | 检出时 |
|---|---|---|
| 一般文本 | LF | 按平台自动 |
| `*.sh` / `*.bash` | LF | **始终 LF**（避免 Linux 报 `bad interpreter: /bin/bash^M`） |
| `*.bat` / `*.cmd` / `*.ps1` | CRLF | **始终 CRLF** |
| 图片/文档/压缩包/jar 等 | 二进制 | 不做任何转换 |

> 若在 Linux 上看到 `deploy/*.sh` 报 `^M`，执行：
> `sed -i 's/\r$//' deploy/*.sh`

## 7. 已知注意事项

1. **不要提交 `models/`、`data/` 大数据**。如需把这些内容也纳入版本管理，
   应使用 Git LFS 而非直接 `git add`，否则仓库会膨胀到数 GB 且无法回退。
2. **`src/frontend-vite-scaffold/`** 是 Vite 脚手架试验件，无 `.gitignore`，
   其 `node_modules/` 由顶层规则排除；确认无用途后可删除。
3. **`src/backend-training/data/`** 下有 2 个示例输入文件
   （`data/出口/merged_output.csv`、`data/进口/merged_input.csv`），供训练上传接口自测，
   已特意在本仓库中保留（该子项目的 `.gitignore` 已改为 `/data/**/*.csv` 白名单规则）。
   其中 `merged_input.csv` 实际是 xlsx 二进制内容被错命名为 `.csv`，
   已在 `.gitattributes` 中显式标为 `binary` 以免被换行转换损坏，使用时注意。
4. **历史备份包 `D:\Code\_git备份_20260927.tar.gz`（112 MB）不在仓库内**，
   它只用于找回合并前的子仓库历史，确认不再需要后可自行删除。

## 8. 凭据与配置管理

项目原先把明文口令、API Key 散落在 20 多个文件里（Python 脚本、Spring YAML、
Go 配置、Vue 源码、Markdown 文档）。由于本仓库**对外公开**，这些已全部清理。

**现在的规则**：

| 规则 | 说明 |
|---|---|
| 唯一存放处 | 项目根 `config/.env`（**已在 `.gitignore` 中排除**） |
| 模板 | `config/.env.example`（入库，只含占位符） |
| 说明 | `config/README.md`（入库，含完整变量清单） |
| 源码约定 | 一律用环境变量占位符 `${VAR:默认值}` 或 `os.getenv()`，**不得出现明文** |
| 默认值 | 保留的默认值均为本地公开默认（如 `123456`），生产环境由 `config/.env` 覆盖 |

**新增配置项时**：先在 `config/.env.example` 与 `config/README.md` 中登记，
再写回 `config/.env`，最后在代码里引用 —— 顺序不要颠倒。

**提交前的自检**：

```bash
# 1. config/.env 必须处于被忽略状态
git check-ignore -v config/.env

# 2. 跟踪列表中不应有任何 .env 实体文件
git ls-files | grep -E '(^|/)\.env$' && echo "!! 有凭据文件被跟踪" || echo "OK"

# 3. 扫描可疑密钥形态
git grep -nE 'sk-[A-Za-z0-9_-]{20,}' -- . ':!config/.env.example'
```

**如果凭据不慎泄露**（改密码没用，必须作废重发）：
详见 `config/README.md` 第 4 节「凭据泄露应急处理」。
