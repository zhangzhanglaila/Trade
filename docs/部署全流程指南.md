# 2. 推荐的最小可运行部署方案

如果你是第一次部署，**强烈建议按“最小可运行方案”启动**，不要一开始就把所有组件都拉起来。

## 2.1 最小可运行方案包含

你至少启动这些：

1. **MySQL**
2. **TDProject-main**（主后端，8080）
3. **TradeSpringBoot**（训练后端，8081）
4. **Python Flask 服务**（5000，通常由 8081 自动拉起，也可手动启动）

以下服务不是第一次启动必须的：

- **Milvus**：用于 AI RAG 向量检索

- **爬虫服务**：默认配置指向 `56887`

如果你只想先把项目页面跑起来、登录、看普通业务页面、跑基础接口，**先不用启动这些扩展服务**。

# 5. 第一次部署最容易踩坑的地方

这一部分非常重要，先看完再配环境。

## 5.1 不要修改 `target` 目录里的文件

项目里存在很多 `target/classes/...` 文件，那是**编译产物**，不是源码。

你应该修改的是：

- `src/main/resources/application.yaml`
- `src/main/resources/application.yml`
- `src/main/java/...`

不要改：

- `target/classes/application.yaml`
- `target/classes/...`

## 5.2 项目里存在硬编码 Windows 路径

尤其是以下路径，换机器通常都会失效：

### 主后端 TDProject-main

- `D:/uploadFiles/`
- `D:/ontology-graph-store`

位置：
- `trade-back\TDProject-main\src\main\resources\application.yaml:26`
- `trade-back\TDProject-main\src\main\resources\application.yaml:31`

### 训练后端 TradeSpringBoot

默认写死了：

- Python 解释器：`D:\programs\Python\Python310\python.exe`（需已装 torch / pandas / flask）
- Python 脚本目录：`D:\Code\Trade\src\backend-training\python-scripts`
- CSV 文件路径：`D:\Code\Trade\src\backend-training\data\{进口,出口}\...`

位置：
- `trade-back\TradeSpringBoot\src\main\resources\application.yml:10`

**你必须按你自己电脑的实际路径改掉。**

## 5.3 AI 千问配置已留空，需要你自己填

主后端 AI 配置当前是：

- `api-key:` 空
- `chat.model:` 空
- `embedding.model:` 空

位置：
- `trade-back\TDProject-main\src\main\resources\application.yaml:54`

如果你要使用 `/ai/chat`、RAG、embedding 相关能力，就必须自己补全。

## 5.4 图谱和爬虫、大屏不是首次部署必须项

前端里虽然有这些页面入口，但：

- 缺哪个扩展服务，就对应页面可能报错
- 不影响前端主页、登录、普通业务接口、训练链路的基础联通

建议第一次部署只保证：

- 3000 前端
- 8080 主后端
- 8081 训练后端
- 5000 Flask
- 3306 MySQL

# 6. 环境准备：MySQL

## 6.1 创建数据库

先登录 MySQL，创建数据库：

```sql
CREATE DATABASE foreign_trade_qa_db DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;
```

## 6.2 导入基础用户表

项目自带用户表 SQL：

- `trade-back\TDProject-main\src\main\resources\db\user.sql`

执行它，至少会创建：

- `sys_user`
- 默认账号：`admin`
- 默认测试账号：`test`

SQL 文件中预置的密码说明：
- `admin` 对应 `admin123`
- `test` 对应 `test123`

> 注意：项目里的 bcrypt 哈希值看起来是同一个，你实际登录时如果失败，优先检查登录接口返回，再考虑重新生成 bcrypt 密码写入数据库。

如果你后续发现与新闻语料相关的 SQL 查询报错，可执行：

# 7. 配置主后端 TDProject-main

配置文件：

- `trade-back\TDProject-main\src\main\resources\application.yaml`

建议你重点检查以下部分。

## 7.1 数据库配置

默认内容：

```yaml
spring:
  datasource:
    driver-class-name: com.mysql.cj.jdbc.Driver
    url: jdbc:mysql://${DB_HOST:localhost}:${DB_PORT:3306}/${DB_NAME:foreign_trade_qa_db}?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai
    username: ${DB_USERNAME:root}
    password: ${DB_PASSWORD:123456}
```

凭据统一放在项目根 `config/.env`（不入库，详见 `config/README.md`），改那里即可。
上面的 `${DB_*:默认值}` 只是让「clone 下来直接跑」不至于启动失败，生产环境会被 `config/.env` 覆盖。

## 7.2 上传目录与本体存储目录

默认内容：

```yaml
upload:
  file:
    location: D:/uploadFiles/

ontology:
  graph:
    store-path: D:/ontology-graph-store
```

建议改成你机器上真实存在、你有权限写入的目录，例如：

```yaml
upload:
  file:
    location: D:/uploadFiles/

ontology:
  graph:
    store-path: D:/ontology-graph-store
```

然后手动创建这两个目录。

## 7.3 AI 千问配置

当前配置结构：

```yaml
ai:
  qwen:
    api-key:
    base-url: ${QWEN_BASE_URL:}
    chat:
      model:
    embedding:
      model:
    endpoints:
      chat: ${QWEN_CHAT_ENDPOINT:}
      embedding: ${QWEN_EMBEDDING_ENDPOINT:}
```

你需要自己填写：

- `api-key`
- `base-url`
- `chat.model`
- `embedding.model`
- `endpoints.chat`
- `endpoints.embedding`

如果你暂时不测试 AI 问答，这块可以先留空，但：

- `/ai/chat`
- `/ai/rag/...`
- embedding 向量构建

这些能力就不能正常工作。

## 7.4 训练服务地址

主后端会调用 8081：

  tradeSpringBoot:

    base-url: http://127.0.0.1:5000

只要你没有改 8081 和 5000，一般不用动。

# 8. 配置训练后端 TradeSpringBoot

配置文件：

- `trade-back\TradeSpringBoot\src\main\resources\application.yml`

这是你第一次部署时最需要手工修改的地方之一。

## 8.1 必改：Python 解释器路径

默认写的是：

```yaml
python:
  interpreter: D:\programs\Python\Python310\python.exe
```

请改成你电脑上实际的 Python 路径（需已安装 torch / pandas / flask），例如：

```yaml
python:
  interpreter: C:\Users\你的用户名\AppData\Local\Programs\Python\Python311\python.exe
```

如果你不确定路径，在终端执行：

```bash
where python
```

把输出路径填进去。

## 8.2 必改：脚本目录路径

默认写的是：

```yaml
python:
  script:
    base-path: D:\Code\Trade\src\backend-training\python-scripts
```

你应该改成当前项目里的真实路径，例如：

```yaml
python:
  script:
    base-path: D:\Code\Trade\src\backend-training\python-scripts
```

## 8.3 必改：训练 CSV 数据路径

当前配置（已对齐本机真实目录）：

```yaml
python:
  data:
    import-data:
      csv-path: D:\Code\Trade\src\backend-training\data\进口\merged_input.csv
    export-data:
      csv-path: D:\Code\Trade\src\backend-training\data\出口\merged_output.csv
```

你要根据当前项目实际目录改成正确路径。

建议改成类似：

```yaml
python:
  data:
    import-data:
      csv-path: D:\Code\Trade\src\backend-training\data\进口\merged_input.csv
    export-data:
      csv-path: D:\Code\Trade\src\backend-training\data\出口\merged_output.csv
```

## 8.4 Flask 自动启动配置

默认：

```yaml
python:
  flask:
    enabled: true
    host: 0.0.0.0
    port: 5000
    readiness-path: /health
    startup-timeout-seconds: 60
```

说明：

- `enabled: true` 表示 8081 训练后端可能会尝试自动拉起 Flask
- 如果自动拉起失败，你也可以手动先启动 `app.py`

## 13.1 `/ai/chat` 依赖什么

1. 主后端 `8080`
2. 千问配置 `ai.qwen.*`
3. 如果走 RAG：还依赖 `Milvus`
4. 如果做新闻向量检索：还依赖新闻语料数据

也就是说：

- **没填千问 API 配置** → `/ai/chat` 大概率不可用
- **没启动 Milvus** → RAG 检索不可用
- **没建立向量索引** → 即使 Milvus 启动了，也可能检索不到结果

## 13.2 训练功能依赖什么

训练链路大致是：

前端 → 8080 主后端 → 8081 训练后端 → 5000 Flask / Python 脚本

所以任意一个环节有问题，训练都可能失败。

最常见原因：

- `application.yml` 里 Python 路径错误
- Python 虚拟环境没装依赖
- CSV 路径不存在
- Flask 没启动
- 8081 无法访问 5000

## 13.3 RAG 索引功能依赖什么

主后端里有 AI RAG 管理接口：

- `/ai/rag/index/full`
- `/ai/rag/index/incremental`
- `/ai/rag/index/recreate`

这些依赖：

1. Milvus 已启动
2. 千问 embedding 配置已填写
3. 新闻数据表里有数据

如果是第一次部署，不建议一开始就测它，先把普通业务和登录跑通。

# 16. 常见报错与处理办法

## 16.1 8080 启动失败：数据库连接失败

典型现象：

- `Communications link failure`
- `Access denied for user`
- 表不存在

处理：

1. 确认 MySQL 已启动
2. 确认库名是 `foreign_trade_qa_db`
3. 确认 `application.yaml` 里的用户名密码正确
4. 确认基础表已经导入

## 16.2 8081 启动失败：Python 路径错误

典型现象：

- 找不到 Python
- 无法启动 Flask
- 脚本执行失败

处理：

1. 修改 `TradeSpringBoot/src/main/resources/application.yml`
2. 把 `python.interpreter` 改成真实路径
3. 把 `python.script.base-path` 改成真实路径

## 16.3 Flask 启动失败：缺少 Python 模块

典型现象：

- `ModuleNotFoundError: No module named ...`

处理：

按报错安装模块，例如：

```bash
pip install flask pandas numpy scikit-learn pymysql
```

## 16.4 前端打开白屏或接口 404

处理顺序：

1. 确认 `npm run serve` 启动的是 3000
2. 确认 8080 已启动
3. 查看浏览器 Network 面板
4. 检查请求路径是否被代理到正确端口

## 16.5 登录失败

检查：

1. `sys_user` 表是否存在
2. 用户是否成功插入
3. 密码 bcrypt 是否匹配
4. 后端日志是否报错

## 16.6 AI 问答失败

检查：

1. 千问 `api-key` 是否填写
2. `base-url` / `endpoint` / `model` 是否填写
3. Milvus 是否启动
4. 是否已建立索引

## 16.7 某些页面打不开但首页能打开

大概率不是主系统完全坏了，而是页面依赖的扩展服务未启动，例如：

- AJ-Report
- 爬虫服务
- 8083 图谱服务
- Neo4j
- Milvus

先确认是不是扩展页面，不要误判为整体启动失败。
