## 一、四个根因

| # | 根因 | 证据 |
|---|---|---|
| 1 | PREDICT 关键词表含**裸词**「进口/出口/单价/数量」，且**排在检索词之前**判断 | 「哈萨克斯坦主要出口哪些商品」被判成 PREDICT |
| 2 | LLM 兜底提示词**只有 PREDICT / RAG_NEWS 两个选项**，没有「闲聊/无关」 | 「你好」被判成 PREDICT（`stage=llm`） |
| 3 | **缺「查已发生数据」这条路** | `trade_in/trade_out` 有 201501~202503 真实数据，而「1月哈萨克斯坦丝绸出口量」被塞进预测、又因四键凑不齐永远给不出答案 |
| 4 | 缺槽位的引导语是**固定模板**，不利用已抽到的槽位 | 无论缺 5 项还是 2 项，尾段"可以这样问…"完全一样 |

## 二、改动

### 路由：两条 → 四条

判定顺序 `CHITCHAT → PREDICT → DATA_QUERY → RAG_NEWS → LLM 四分类`：

- **PREDICT** 必须出现前瞻词（预测 / 预估 / 预计 / 下月 / 未来 / 会是多少 / 明年 …）；
- **DATA_QUERY** 条件为 `贸易词 && (查询词 || 出现年月)`，且**必须排在 RAG 之前**，
  否则「最近三个月…是多少」会被"最近"劫持；数据查询**不把年月缺省成下个月**（预测才缺省）；
- **CHITCHAT**：≤12 字且命中寒暄词，或命中「你是谁 / 你能做什么 / 怎么用」；
- **LLM 兜底提示词同步改为四分类**（这是「你好」被判成预测的直接原因）。

### 历史数据查询（新增 `ai/query/TradeDataQueryService`）

- 复用主 DataSource + 跨库限定名查 `trade` 库，无新增连接配置；
- 商品名解析：精确 → 全串 LIKE（唯一才采用）→ 2-gram 打分 → 单字兜底给候选；
- 未来月份 → 明确说明"库中最新 2025-03"并引导改用预测；
- **未指定商品时不给数量合计**：不同商品计量单位不同（千克/米/台/株…），
  相加会得到假数字（实测「2025年3月哈萨克斯坦出口数量」曾算出 `501,181,485 米`）。
  改为只给金额并说明原因。

### 差异化引导

预测缺槽位时输出「已识别 / 还缺 / **该商品+伙伴在库中的贸易方式与注册地实际取值**」，
示例句随已识别槽位变化；商品名不在库中时直接给出规范名候选。

### 前端

路由标签按四类区分文案与颜色；`DATA_QUERY` 展示按月明细表；
**预测结果卡片只在有值时渲染**（此前无值也渲染，页面出现 `value=- / unit=-` 的空表格）。

## 四、运维备忘

- **重启 backend-main** 用专用脚本（`source config/.env` 取 `JWT_SECRET` → 停旧进程 →
  等 8080 真正释放 → 启动）。**不要**用 `deploy/start-all.sh`：它见端口占用会 `[跳过]`
  并正常退出，上层会误判"重启成功"，实际跑的还是旧进程。
- 前端改完必须 `npm run build`；nginx 直接 root 到 `dist`，构建完即生效。
  两次构建叠加会残留无引用的 `app.<hash>.js`，以 `index.html` 引用为准，其余可删。
- 请求体字段名是 **`text`**（无 `question` 别名）。传错不报错，而是静默变成空输入，
  表现为「route 对、槽位全空」——排查时先确认字段名。
